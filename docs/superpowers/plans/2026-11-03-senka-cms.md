# Senka CMS + Gallery Sites Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A small headless CMS on Cloudflare (free tier) that two non-technical artists use to manage works (images or videos, custom text details, tags), plus a fast white-wall gallery site for each artist that reads from it.

**Architecture:**
- It's a pnpm monorepo with two Cloudflare Workers sharing one D1 database and one R2 bucket.
- **`apps/admin`** (`senka-admin`): a React 19 SPA built with Vite and served as static assets, plus a Hono JSON API under `/api/*`. The whole hostname sits behind Cloudflare Access.
- **`apps/sites`** (`senka-sites`): a public Astro 7 SSR Worker. It renders both portfolios at `/<site-slug>/…` and later on custom hostnames. It also serves `/api/public/*` and `/media/*`. Its UI is written as React components rendered on the server only. There are no `client:*` directives, so the pages ship zero JavaScript.
- **Onlook:** all UI in both apps is React, so the Onlook desktop app can edit it visually. Onlook's own docs list "Astro with React", Vite, CSS Modules and Vanilla CSS as supported.
- **`packages/core`**: all SQL, types, validation and the public data shape, so both apps run the same queries.

**Tech Stack:**
- **Frameworks:** Astro ^7.4, `@astrojs/cloudflare` ^14.4, `@astrojs/react`, React ^19, Vite, `@vitejs/plugin-react`, `@cloudflare/vite-plugin`, Hono ^4
- **Libraries:** jose ^6, zod, lucide-react, `@fontsource-variable/*`
- **Testing extras:** `@testing-library/react`
- **Design tool:** Onlook desktop app (early access), used for visual design edits
- **Tooling:** wrangler ^4.125, Vitest + `@cloudflare/vitest-pool-workers`, TypeScript strict, pnpm

**Spec:**
- `docs/design-spec.md` (UI and design tokens)
- `.claude/session-plan.md` + `.claude/session-intent.md` (product scope)
- `~/.claude-octopus/results/probe-synthesis-1793717858.md` (verified platform facts and edge cases)

Executors read all three.

## Global Constraints

- **Free plan only.** No paid Cloudflare products (Stream, Images paid, Workers Paid) and no third-party auth or email services.
- **Workers, not Pages.** The Astro adapter targets Workers only. Read bindings with `import { env } from "cloudflare:workers"`. Never use `Astro.locals.runtime`.
- **wrangler:** every `wrangler.jsonc` uses `"compatibility_date": "2026-10-01"` and `"compatibility_flags": ["nodejs_compat"]`.
- **Shared resources:** one D1 database (`senka-db`, binding `DB`) and one R2 bucket (`senka-media`, binding `MEDIA`), bound in both Workers. Migrations live in `/migrations`, and both wrangler configs set `"migrations_dir": "../../migrations"`.
- **10ms CPU per request on the free plan.** No per-request JSON transforms over full tables and no image processing in Workers. Images are resized in the browser.
- **Single request body cap: 90 MB.** Uploads larger than `MAX_UPLOAD_BYTES = 90 * 1024 * 1024` are rejected on both the client and the server.
- **Site scoping.** Every query that touches site-owned rows takes `siteId` and filters `WHERE site_id = ?`. `siteId` comes only from the authenticated user (admin) or the resolved site (sites), never from request bodies.
- **Copy:** use "Details" (never "fields"), "Visible on site" / "Hidden" (never "published/draft") and "Add work". Never use `alert()`, `confirm()` or `prompt()`.
- **Design:** tokens, components, breakpoints and copy come from `docs/design-spec.md` verbatim.
- **Styling:**
  - Global design tokens live as CSS custom properties in `tokens.css`.
  - Component styles go in CSS Modules (`Component.module.css`), placed next to each `.tsx` file.
  - No Tailwind, no CSS-in-JS, no UI kit.
- **Onlook-editable code:**
  - All UI is React function components in `.tsx` files, with one component per file. Props are plain serialisable data, and components don't fetch data.
  - In `apps/sites`, `.astro` files only load data and render one top-level React component with props. Keep the markup inside `.astro` files to just `<head>` and that one component.
  - Use visible JSX, not markup generated from loops of config objects, so Onlook can map each element to source.
- **Per-app dev servers:** each app runs on its own with `pnpm dev` from its own folder (`apps/admin`, `apps/sites`), because Onlook opens one app folder at a time and starts its dev server.
- **Accessibility:** inputs use `font-size: 16px`. Touch targets are at least 44×44px. Every interactive element has the visible `--focus` ring.
- **Media keys:** R2 object key = `${siteId}/${mediaId}/${variant}`, where variant ∈ `original | w480 | w1200 | w2400 | poster`. Store the content type in R2 `httpMetadata.contentType`.
- **Site placeholders:**
  - `site-a`: name "Site A", preset `grotesk`
  - `site-b`: name "Site B", preset `serif-title`, accent `#7A3E2E`
- **Commits:** each task ends with a commit. Messages use conventional prefixes (`feat:`, `test:`, `chore:`, `docs:`) and end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **iPhone HEVC `.mov` upload.** The admin warns with the spec's exact copy, and the user can still keep the file. Owner: Task 9 (`sniffHevc` tests).
2. **File over 90 MB.** The client rejects it before uploading with "This file is over 90 MB. Try exporting a shorter or smaller version." The server returns 413 if bypassed. Owners: Task 7 (server) and Task 9 (client).
3. **Video seeking.** `GET /media/*` with a `Range` header returns 206 with a correct `Content-Range`. Without it, Safari won't play or seek videos. Owner: Task 12.
4. **Hidden works, pending media and soft-deleted works must never leak publicly.** This covers slug guesses in the site and public API, and appearing in tag pages or sitemaps. Owners: Task 4 (`listPublicWorks`) and Task 12 (route tests).
5. **Saving the same work from two tabs.** The stale save gets 409 and doesn't overwrite. Owners: Task 3 (`updateWork`) and Task 6 (route).

CREATE TABLE sites (
  id INTEGER PRIMARY KEY, slug TEXT NOT NULL UNIQUE, name TEXT NOT NULL,

  id INTEGER PRIMARY KEY, site_id INTEGER NOT NULL REFERENCES sites(id),

  visible INTEGER NOT NULL DEFAULT 0, sort REAL NOT NULL DEFAULT 0,
  fields_json TEXT NOT NULL DEFAULT '{}', cover_media_id INTEGER,

CREATE INDEX works_site_sort ON works(site_id, deleted_at, sort);
CREATE TABLE media (
  id INTEGER PRIMARY KEY, site_id INTEGER NOT NULL REFERENCES sites(id),
  work_id INTEGER REFERENCES works(id),
  kind TEXT NOT NULL CHECK (kind IN ('image','video')),
  status TEXT NOT NULL DEFAULT 'pending' CHECK (status IN ('pending','ready')),
  mime TEXT NOT NULL, width INTEGER NOT NULL, height INTEGER NOT NULL,
  duration REAL, color TEXT, alt TEXT NOT NULL DEFAULT '',
  variants_json TEXT NOT NULL DEFAULT '[]', bytes INTEGER NOT NULL DEFAULT 0,
  sort REAL NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ','now')));
CREATE INDEX media_work ON media(work_id, sort);
CREATE TABLE tags (
  id INTEGER PRIMARY KEY, site_id INTEGER NOT NULL REFERENCES sites(id),
  name TEXT NOT NULL, slug TEXT NOT NULL, UNIQUE (site_id, slug));
CREATE TABLE work_tags (
  work_id INTEGER NOT NULL REFERENCES works(id) ON DELETE CASCADE,
  tag_id INTEGER NOT NULL REFERENCES tags(id) ON DELETE CASCADE,

  - **`range.ts`:** `parseRange(header: string | null, size: number): { offset: number; length: number } | null | "invalid"`. It supports `bytes=a-b`, `bytes=a-` and `bytes=-n`, and returns `"invalid"` when the range can't be satisfied.
  - **`media/[...key].ts` GET:**
    - The key must match `^\d+/\d+/(original|w480|w1200|w2400|poster)$`, otherwise 404.
    - `MEDIA.head` the object for its size, then `MEDIA.get(key, { range })`.
    - Respond 200 or 206 with `Content-Range: bytes a-b/size`, `Accept-Ranges: bytes`, the stored `Content-Type`, `Cache-Control: public, max-age=31536000, immutable` and an `ETag`.
    - An invalid range gets 416.
    - The media row must be `ready` and its work visible and not deleted (one D1 query by id parsed from the key), otherwise 404.
  - **`site.ts`:** `resolveSiteFromRequest(db, url: URL): Promise<{ site: Site; basePath: string } | null>`

  - **`media.ts`:** `mediaBase(env): string`, which returns `env.MEDIA_BASE`.
  - **`cache.ts`:** `withVersionCache(request: Request, version: number, ctx: ExecutionContext, render: () => Promise<Response>): Promise<Response>`

    - The cache key is the request URL with `__v=<version>` appended, stored in `caches.default`.
    - The response is stored with `Cache-Control: public, s-maxage=86400`, while the browser receives `Cache-Control: public, max-age=0, must-revalidate`.
    - On workers.dev it may be a no-op; that's acceptable.
  - **`middleware.ts`:**
    - For a custom hostname, rewrite `/x` to `/<slug>/x` (Astro `context.rewrite`).
    - For `/[site]/**` and `/api/public/**`, resolve the site and wrap the response in `withVersionCache`.

  - **Public API (JSON, `Access-Control-Allow-Origin: *`):**
